# ADR-0001. Ручной способ деплоя TimeCapsule

- Статус: принято
- Дата: 2026-10-07

## Контекст

Для лабораторной работы необходимо развернуть PHP-приложение TimeCapsule
на одном экземпляре Amazon EC2. Исходный код хранится в публичном
репозитории GitHub организации `mihailovschi-cloud`.

По условию работы для специальности Informatică aplicată выбран вариант A:
ручное обновление приложения на сервере. Необходимо обеспечить понятный
и повторяемый порядок получения новой версии кода, установки зависимостей,
инициализации базы данных и обновления PHP-FPM.

## Решение

Используется ручной деплой через SSH-подключение к экземпляру EC2.
После отправки изменений в GitHub выполняются следующие команды:

```bash
cd /var/www/timecapsule
git pull
composer install --no-dev --optimize-autoloader
php bin/init-db.php
sudo systemctl reload php-fpm
```

GitHub является единственным источником исходного кода. На сервере не
выполняется ручное изменение файлов приложения. Откат выполняется через
`git revert` в локальном репозитории, после чего исправление отправляется
в GitHub и разворачивается на сервере.

## Рассмотренные альтернативы

### Копирование файлов через scp

`scp` подходит для передачи небольшого статического сайта, но неудобен для
полноценного приложения. При таком способе сложно определить, какая версия
кода работает на сервере, легко забыть отдельный файл и неудобно выполнять
откат изменений.

### Ручной git pull на сервере

Этот вариант был выбран для лабораторной работы. Код централизованно хранится
в GitHub, а сервер получает конкретную версию через Git. Разработчик вручную
выполняет установку зависимостей, инициализацию базы и перезагрузку PHP-FPM.

### Скрипт deploy.sh

Скрипт мог бы объединить ручные команды в одну и уменьшить вероятность
пропустить шаг. Однако для специальности Informatică aplicată по условию
работы используется вариант A, поэтому отдельный скрипт не создавался.

## Последствия

- Плюс: код хранится в GitHub, история изменений прозрачна, а откат можно
  выполнить через `git revert`.
- Плюс: процесс развёртывания понятен и позволяет контролировать результат
  каждой команды.
- Минус: деплой запускается вручную, поэтому разработчик может забыть один
  из шагов или допустить ошибку.
- Минус: во время `git pull` посетитель теоретически может получить
  промежуточную версию приложения.
- Минус: отсутствуют автоматические тесты, staging-окружение и
  автоматический CI/CD-деплой.
